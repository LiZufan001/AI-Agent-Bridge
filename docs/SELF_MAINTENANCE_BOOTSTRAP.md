# Split self-maintenance: broad-read, narrow-write Codex permissions

Source repository: Public Engine. Canonical maintenance command/report/Goal/Owner records: Private State. Proposed maintenance workdir: an independent Engine-maintenance clone, never running Engine, State, or a linked worktree sharing authority. No extra daemon or repository synchronization protocol is needed.

**Split self-maintenance execution is admitted only after independent-clone preflight, and unattended adoption remains disabled.** Ordinary Bridge commands keep the existing full-access Codex mode. A self-maintenance run is rewritten locally to a Codex permissions profile that extends built-in `:workspace`, adds `:root = read`, enables public network access, and sets approval policy to `never`. The validated Candidate remains the runtime workspace; built-in `:workspace` keeps Candidate and ordinary system temporary directories writable while preserving protected workspace paths such as `.git` as read-only. Production Engine, Private State, Legacy, and other host paths are readable but not writable. No legacy `--sandbox`, `-C`, `--cd`, or `--add-dir` authority is admitted. Manual controlled adoption still requires both an operator-installed Private State `worker/deployment.local.json` binding and the outer Launcher's explicit `--allow-controlled-adoption` startup flag.

The candidate-generation workflow is now an unattended Codex run inside the Candidate workspace, followed by the existing post-run identity/protected-path guard, CI and independent review. After an operator accepts a candidate, installs the exact deployment binding and explicitly arms the outer Launcher, the existing manual handoff consumer may perform controlled adoption from independently prepared handoff evidence while admissions are drained; its restart evidence lives under State runtime and replacement Workers are explicitly rebound to the same State root. Running Engine and State remain protected paths. A candidate may edit only its independent Engine workdir. State validation must run from an accepted immutable Engine SHA chosen outside the candidate's control; it cannot self-approve by changing its own validator and reference together.

The source package proves run-local policy selection and fail-closed argv construction, but actual native-Windows permissions-profile enforcement still needs host acceptance before this phase is treated as production-complete. No fallback to full access is permitted for a self-maintenance run. System TEMP write access is intentional disposable scratch, not a failure condition. Protected Candidate `.git` remains outside the maintenance Agent's mutation authority, so commit creation and deployment stay with the trusted outer authority. Ordinary non-maintenance projects retain their existing full-access execution model.

Engine rollback with the same compatible State schema must preserve canonical State and local recovery evidence. Rollback to an old combined repository is different: after any canonical mutation, stale combined-repository State is not a lossless rollback target. Never copy State backward or rewind generation automatically.
