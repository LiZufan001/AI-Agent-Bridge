# Protocol v2 invariants

These rules are deliberately short. They are the cross-component truths that Supervisor, Worker, manual fast lane, recovery logic, and future tooling must all preserve.

1. **One canonical pointer.** `projects/<project-id>/state.json` is the only canonical current project pointer. Commands, reports, owner-actions, owner-feedback, alerts, and local journals are evidence/history, not alternate canonical state.
2. **Append-only history.** Published `command-*.md`, `report-*.md`, `owner-action-*.md`, and `feedback-*.md` history is immutable. Corrections, progress, acceptance, and supersession use new ids; stale/orphan files may remain non-canonical.
3. **CAS before mutation.** Work prepared against generation `G` must not overwrite a state that has advanced beyond `G`. A lost race is an abort/re-evaluate event, never permission to force-push stale state.
4. **Single execution lease.** `CODEX_RUNNING` requires one matching `active_run`. Only the holder of the exact run id and claimed generation may publish that run's report.
5. **No blind rerun.** Git races, network interruption, Worker crash, lease expiry, or uncertain side effects never justify automatically rerunning the original Codex command.
6. **Recovery is identity-bound.** Deferred recovery may mutate canonical state only when project, command, run id, generation, and claimed-generation evidence still identify the exact interrupted run.
7. **Recovery Resolution is evidence-only.** A `RECOVERY_REQUIRED` resolution may publish only evidence for the already interrupted run. It must never launch, claim, replay, or continue Codex.
8. **Recovery report identity is exact.** The resolution report must match the exact project, command id, run id, claim generation, source, and based-on report, and must bind the operator-reviewed pending-report SHA-256.
9. **Executor does not self-approve completion.** Worker/Codex may publish reports but only the Supervisor may move a verified final delivery to `DONE`.
10. **Human work is orthogonal.** `HUMAN_REQUIRED` is the canonical project gate. `AWAITING_OWNER`, `OWNER_IN_PROGRESS`, and `OWNER_REPORTED_DONE` are append-only owner-action progress values; none is a top-level Bridge state.
11. **Owner self-report is not verification.** `OWNER_REPORTED_DONE/PENDING` is a verification trigger, not proof. `VERIFIED` requires concrete current evidence.
12. **Late owner feedback never mutates in-flight work.** Owner feedback may be recorded while a command is pending or running, but it must not rewrite a published command, alter a claimed task snapshot, change the active lease/generation/state, or create competing work. It is reconciled at the next safe planning boundary.
13. **Implementation is not owner acceptance.** Codex/report success may support an `IMPLEMENTED` feedback status, but `OWNER_ACCEPTED` requires explicit later owner feedback.
14. **Notifications are side effects.** Alert/email bookkeeping must not change protocol generation, leases, recovery identity, or execution outcome.
15. **Secrets stay out of the bus.** Private authentication material and equivalent secrets must not enter commands, reports, owner-actions, owner-feedback, canonical state, or alert evidence.
16. **One fact, one authority.** Avoid duplicating mutable facts across canonical fields. Compatibility fields such as `human_required` are subordinate to `status` and must never contradict it.
17. **Unclaimed repair is narrow and evidence-only.** An operator may supersede only the exact canonical, unclaimed `COMMAND_READY` command when its complete deterministic pre-claim contract is invalid, including Protocol metadata or an optional strict body-format contract such as the phased-task parser. The replacement is a new append-only command with an exact historical `supersedes_command_id` relation; repair consumes one generation and never claims, executes, reports, or enters recovery.
18. **Canonical commands are preflight-valid exact bytes.** Before a publisher makes a command canonical, the exact final bytes that will be committed must pass the complete deterministic, side-effect-free pre-claim validation set, including Protocol metadata/state-relative identity and any declared optional body parser. Metadata-only or template-only validation is insufficient; any byte change after preflight requires revalidation. A deterministic preflight failure stops before canonical mutation. See `protocol/v2/PUBLICATION_PREFLIGHT.md`.
19. **SUCCESS acceptance is evidence-based and risk-proportional.** A Worker/Codex `SUCCESS` report is evidence, not self-approval. The Supervisor independently verifies the smallest sufficient exact evidence set and must not default to redundant full re-execution. Review escalates only when consequence, uncertainty, contradictory evidence, or missing mechanical coverage justifies deeper inspection. See `policies/success-review.md`.
20. **Staged repair adoption is pointer-only.** When a valid replacement command already exists in immutable history, the operator may adopt it only from the exact idle canonical queue boundary with byte/hash-bound state and command evidence. The CAS payload contains only `state.json`; both command files remain byte-for-byte unchanged, and no run, lease, report, recovery record, or executor action is created.

If an implementation cannot determine that all relevant invariants still hold, it must stop conservatively rather than infer progress.
